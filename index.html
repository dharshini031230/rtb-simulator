i

Educational first-price auction simulation, not a production advertising auction. Every calculation runs locally in your browser using simulated data. No bid requests are transmitted and no real exchange, SSP or DSP is contacted. Real exchanges also apply bid floors, timeouts, fraud filtering, privacy controls, fees and their own pricing rules.

An independent educational project. It is not affiliated with any advertising exchange or ad-tech provider.

    Timestamps are illustrative, not measured. Values such as t+42ms are drawn from fixed ranges to show the order and rough proportions of each stage. This page runs no real-time auction and measures no network latency.

      Animation duration vs. real RTB latency

      The animation pauses about 550ms per stage (none if your system requests reduced motion), so one run takes roughly 2.75 seconds. That delay exists only to make each stage readable.

      In production, the exchange sets a response deadline in the bid request (tmax, 120ms here), and the whole auction has to finish while the page is loading. Real latency depends on network distance, bidder infrastructure and exchange configuration, and this simulator models none of it.

      The bid request

      An illustrative, OpenRTB-inspired bid request, generated each time an auction runs. It uses field names and enumerated values from OpenRTB 2.6, but it is intentionally minimal. It is not a complete or certified production request.

      bid-request.json 
      
          
      
          
      
        
      

        
      
          
      Field annotations
      
          
      
            
      id
      Unique ID of this bid request, generated by the exchange. Bidders echo it in their bid response.
      
            
      test
      1 marks test mode, meaning the auction is not billable. That suits a simulation.
      
            
      at
      Auction type. 1 = first price, 2 = second price plus.
      
            
      tmax
      Maximum time in milliseconds the exchange waits for bids, including network latency.
      
            
      cur
      Currencies the exchange accepts for bids, as ISO-4217 codes.
      
            
      imp[]
      The impressions on offer. Each has its own id. Here there is one 300×250 banner, described by banner.format.
      
            
      imp.bidfloor
      Minimum acceptable bid, expressed in CPM. bidfloorcur gives its currency.
      
            
      imp.secure
      1 requires an HTTPS-safe creative.
      
            
      site
      Where the ad will appear: domain, full page URL and publisher.
      
            
      device.devicetype
      A numeric enumeration (AdCOM List: Device Types), not a string. 1 = Mobile/Tablet. More specific values are 4 = Phone and 5 = Tablet.
      
            
      device.geo.country
      Country as an ISO 3166-1 alpha-3 code, for example USA.
      
          
      
        
      
      
      

      
      
        
      What a real exchange does differently: it usually sends a request like this to many DSPs in parallel, often with extra signals such as user agent, IP-derived geography, consent strings and supply-chain objects. It then waits up to tmax for bid responses. This simulator transmits nothing. The JSON is built and displayed in your browser, and the advertisers you configure stand in for DSP bid responses.
      
      
      
    
      

    
      
      
      Under the hood
      
      
      How the auction is implemented. Every snippet below is copied from auction-core.js, the DOM-free module that both the UI and the automated tests use.
      

      
      
        
      
          01 · Input validation
          
      Names and bids are checked before ranking
      
          
      Names are trimmed and must be 1–40 characters. Bids must match a strict pattern: digits with an optional decimal part of one or two digits. Symbols such as $, commas and exponents like 1e3 are rejected. Every failure returns a stable error code, such as BID_NEGATIVE, plus a readable message.
      
          
      const BID_PATTERN = /^\d+(\.\d{1,2})?$/;
      
          
      if (name === "") {
  return issue("NAME_EMPTY", "Name is empty. Every bidder needs a name so the result can identify it.");
}
      
        
      

        
      
          02 · Integer arithmetic
          
      Money is compared in integer cents
      
          
      Binary floating point cannot represent most decimal fractions exactly, so 0.1 + 0.2 === 0.3 is false in JavaScript. Validated bid strings are split on the decimal point and turned into whole cents without using parseFloat, so every comparison is between exact integers.
      
          
      function toCents(bid) {
  const [whole, fraction = ""] = bid.split(".");
  return Number(whole) * 100 + Number(fraction.padEnd(2, "0"));
}
      
        
      

        
      
          03 · Bid ranking
          
      Valid bids are sorted highest first
      
          
      Rejected entries are filtered out. The rest are sorted by cents in descending order. When two amounts are equal, the comparator falls back to each bid's original index.
      
          
      const validBids = evaluated
  .filter(function (b) { return b.valid; })
  .sort(function (a, b) { return b.cents - a.cents || a.index - b.index; });
      
        
      

        
      
          04 · Tie-breaking
          
      Submission order decides equal bids
      
          
      Because the sort puts the lower index first, the earliest submitted bid becomes validBids[0]. The tie group is reported separately so the UI can explain the decision. Real exchanges define their own rules, and some pick randomly.
      
          
      const tiedBids = winner
  ? validBids.filter(function (b) { return b.cents === winner.cents; })
  : [];
      
        
      

        
      
          05 · First-price pricing
          
      The winner pays its own bid
      
          
      In a first-price auction the clearing price equals the winning bid, and the runner-up has no effect on it. That is why bidders in first-price markets often "shade" their bids below their true valuation.
      
          
      clearingPriceCents: winner ? winner.cents : null, // first-price: winner pays own bid
      
        
      

        
      
          06 · No-fill handling
          
      No valid bids means no sale
      
          
      If nothing survives validation, there is no winner and no clearing price. The result has status: "no-fill" and a reason that separates an empty auction from one where every bid was rejected.
      
          
      if (!winner) {
  noFillReason = evaluated.length === 0 ? "NO_BIDDERS" : "ALL_BIDS_REJECTED";
}

      Learn the fundamentals
      
      
      The vocabulary you need to read any programmatic advertising documentation.
      

      

      
      
        
      
          Programmatic
          
      Programmatic advertising
      
          
      Buying and selling ad space through software and automated rules, not manual insertion orders. Decisions are made per impression, using data about the slot and context.
      
        
      
        
      
          RTB
          
      Real-Time Bidding
      
          
      A form of programmatic buying in which each impression is auctioned individually while the page or app loads, typically within a few hundred milliseconds.
      
        
      
        
      
          DSP
          
      Demand-side platform
      
          
      Software that bids on behalf of advertisers. It evaluates each bid request against campaign targeting, pacing and budget, then decides whether to bid and how much.
      
        
      
        
      
          SSP
          
      Supply-side platform
      
          
      Software that publishers use to sell inventory. It connects ad slots to demand sources, enforces floors and rules, and aims to maximise publisher yield.
      
        
      
        
      
          Ad exchange
          
      The marketplace
      
          
      The venue that receives inventory, sends bid requests to DSPs, runs the auction and returns the winning creative. Many SSPs operate their own exchange.
      
        
      
        
      
          CPM
          
      Cost per mille
      
          
      Price per 1,000 impressions. Bids are quoted in CPM even though each auction sells a single impression.
      
          
      price per impression = CPM ÷ 1000
      $3.20 CPM → $0.0032
      
        
      
        
      
          Request / response
          
      Bid requests and bid responses
      
          
      A bid request describes the impression on offer, as in the JSON above. A bid response is the DSP's reply: a seatbid containing a bid with a price and creative markup, or no bid at all.
      
        
      
        
      
          Auction models
          
      First-price vs. second-price
      
          
      First-price: the winner pays its own bid. Second-price: the winner pays roughly the runner-up's bid plus a small increment. With bids of $3.20 and $2.80, first-price clears at $3.20, and a second-price auction with a $0.01 increment would clear at $2.81. This simulator implements first-price only.
      
        
      
      
      
    
      

    
      
      
      How this project works
      
      
      A static site with no build step. All auction calculations happen locally in the browser. There is no backend, no database, no external API integration and no actual DSP connection.
